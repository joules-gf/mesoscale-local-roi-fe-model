# Workflow and interfaces

## Macroscopic response

`full_simulation_runner.py` connects input generation, Abaqus submission and macroscopic postprocessing. `abaqus_input_generation_v02.py` expands XML includes, completes parameters and writes the mesh/deck. `material_reference.py` selects reference data and resolves E=auto. `wsl_windows_compat.py` provides platform launching.

`getForceDisp.py`, executed by Abaqus, independently sums bottom-node reactions and averages upper-node displacement. Its CSV contains one metadata line followed by the header. The present force/displacement interpretation assumes unit geometry; verify dimensions before using another domain.

For a data-only run that must not produce final comparison plots, call generation and submission, then `postprocessing_abaqus_sim_v01.extract_force_displacement`; do not call its complete plotting sequence. Keep the solver inputs and generation/global-extraction sources frozen while the case runs.

## Current local workflow: direct signed PE22

The current exporter requests **S/S22 and PE/PE22** at integration points. PE22 is the signed normal plastic strain component in direction 2; it is not PEEQ. No elastic subtraction, clipping, positive floor or small-value threshold is applied in the direct summary path.

1. Inventory the original ODB read-only with `00_Main_Scripts/abaqus_odb_frame_inventory.py` under Abaqus Python/CAE, from the case's original `abaqus_files` directory. `ODB_FILE` may specify the stem or filename; otherwise exactly one ODB must be present. Set `ODB_INVENTORY_OUTPUT=../odb_inventory_pe22.json` to preserve an earlier inventory. It records actual frame indices, times, increments, fields, component labels, instance and bounds, without creating sets or saving the ODB.
2. From the repository root, match global stress peak times to those actual frames:

```text
python 00_Main_Scripts/peak_detection.py --case-folder "CASE" --frame-inventory "CASE/odb_inventory_pe22.json" --output-json "CASE/peak_selection_pe22.json"
```

`--csv GLOBAL.csv` can replace `--case-folder`. Multiple inventory steps require an explicit `--step-name`. The current ROI exporter uses the first step; this workflow is for the single Step-1 generated by the runner. Do not select another step without extending that exporter. Peak times are never implicitly multiplied by 100. API callers without an inventory receive times and None frame indices; historical scaling requires explicit `time_to_frame_scale=100`.

3. Create a separate `roi_work_pe22` ODB copy. Never use the only original: the ROI exporter opens its selected working copy writable and adds element sets. Hash-check the copy before using it.
4. In that working directory, write `roi_report_config.json` naming the working ODB, actual instance, matched frame indices, radius/count/spacing and `output_folder="../roi_reports_pe22"`. Disable backup creation/restoration when the original is separately preserved. Validate configuration before writable access; check selected frames against the inventory.
5. Run Abaqus/CAE with the absolute path to `00_Main_Scripts/abaqus_roi_report_export.py`. It exports the ROI reports and `domain_pe22_summary.csv` for those same frames and instance. The domain file contains the signed equal-point PE22 mean, extrema, sign/zero counts and point count. It supports one meshed CPS3 instance, with one integration point per element, and excludes node-only reference instances. Missing, duplicate, foreign or nonfinite points fail validation.
6. Require all expected reports and the domain CSV after CAE execution. A CAE script exception can occur with shell exit status zero; validate artifacts rather than trusting the return code alone. JSON Unicode text is normalized at Abaqus Python 2 native API boundaries. Avoid bare sum(generator) in CAE sign counting because the kernel can shadow Python's sum.
7. Calculate actual ROI phase areas and summarize direct PE22:

```text
python 00_Main_Scripts/roi_area_fractions.py --input-deck "CASE/abaqus_files/CASE_NAME.inp" --output-csv "CASE/roi_reports_pe22/roi_area_fractions.csv"
python 00_Main_Scripts/roi_postprocessing.py --roi-reports "CASE/roi_reports_pe22" --plastic-strain-source pe22 --area-fractions-csv "CASE/roi_reports_pe22/roi_area_fractions.csv"
```

A previously verified area CSV for the same unchanged final deck may be reused by passing its actual path. Direct folder summaries identify `plastic_strain_source=PE22`. PE column lookup strips Abaqus header padding, including the actual seven-space `PE-PE22` prefix, but does not rewrite raw reports. Duplicate normalized headers or missing/nonfinite PE22 are errors, never a reason to fall back to subtraction.

8. Inspect ROI-average ranges and positive/zero/negative counts at each selected peak, along with the whole-model mean, before deciding how to display them. The sign of a tensor component is meaningful. Keep zeros and small values intact.

**Explicit ordinary-log PE22 plotting:** the legacy orchestration/CLI rejects PE22 summaries. Use `make_pe22_log_plots(roi_summary_csv, cycle_csv, domain_pe22_csv, area_fractions_csv, output_root, material_label=None)` from `roi_plotting.py` for the user-approved direct-field figures. It validates all inputs first, uses the actual direct whole-model PE22 reference, and generates grouped full-response and stress-indicator/area plots for each saved frame, with four phases separate.

The approved display is `abs(signed ROI mean PE22)` and `abs(signed whole-model mean PE22)` on ordinary log axes. It is **not** the mean of pointwise absolute values. Signed CSVs are not modified. Exact zeros are open markers with `0` in a separate below-axis band, never positive log-axis values or invented floors. Nonzero values below the historical floor are retained. Axis labels are `Stress (S22), MPa` and `Plastic strain (PE22)` with the existing log-scale note; the magnitude convention is disclosed in the generation record and accompanying captions instead of adding words to the requested axis labels. Stress and stress-based indicators remain signed. `plot_generation.json` records input hashes, signed/display values, zero locations and output paths. Final thesis integration is a separate step.

## Phase area calculation

`roi_area_fractions.py` reads every triangle and material assignment from the final solved deck. It includes triangles that intersect a semicircle even when their centroids lie outside. Each phase contributes only its triangle/ROI overlap area, divided by the full semicircle area. Circular arcs are integrated directly. Invalid material ownership, overlapping triangles and incomplete coverage are rejected rather than normalized away.

Supported geometry is one untransformed planar CPS3 part/instance or orphan mesh, with the default unit-square edge layout. The area CSV and JSON sidecar record the deck hash, geometry, reference coordinates, units and coverage errors. Stress and PE22 averages retain the agreed centroid-selected, equal-element convention; the area calculation does not turn those field averages into area-weighted averages.

## Explicit historical reproduction

The summary CLI defaults to `--plastic-strain-source pe22`. Its Python APIs retain a legacy default for existing reproduction callers, so new code must explicitly pass `plastic_strain_source='pe22'`.

To reproduce the former estimate from an archived S22/E22 report:

```text
python 00_Main_Scripts/roi_postprocessing.py --roi-reports "HISTORICAL_CASE/roi_reports" --plastic-strain-source legacy --youngs-modulus-mpa SAVED_CASE_E --output-csv "HISTORICAL_CASE/roi_reports/roi_summary_reproduced.csv"
```

Legacy mode alone uses rowwise E22-S22/E, clipping and the historical 0.00025 cutoff. Keep those historical outputs separate from new PE22 reports. The legacy plotting API also has a 71000 MPa default; it is not a direct PE22 plotting path.

The older example chain under `simulation_inputs/Uniform Distribution/examples/` retains its original T6 parameters and distribution. It is not the new normal baseline.

## Material baseline inputs and provenance

`simulation_inputs/AA2024-T351/` and `simulation_inputs/AA7075-T651/` contain local baseline mesh/parameter includes and uniquely named monotonic and R=-1 cyclic cases. Both use normal diameters with mean 0.050 mm, omitted scale completed as 0.010 mm, fresh restart=False and E=auto. See each README for material properties and commands.

Keep exact inputs, effective settings, source hashes, mesh/deck, successful solver status, ODB, global extraction version, actual frame selection, ROI configuration and report/summary provenance together. Passing software tests or finding a CSV alone does not establish a completed solve or independent physical validation.
